## 二、核心决策：做深而不是做广（不变）

### 2.1 战略选择

```
选项A: 做广 — 助教+助学+助研全场景覆盖
  风险: 精力分散，每个场景都浅，沦为功能堆砌
  结果: 平庸的"全场景平台"，评委看腻了

选项B: 做深 — 聚焦一个真实痛点，打穿打透  ← 我们的选择
  风险: 场景覆盖面窄
  结果: 在一个痛点上做到极致，让评委记住你
```

比赛评审维度中，"创意实用度(20分)"要求：

```
建设成果:
├── 教材知识库: 7本AI Agent中文教材PDF → 2402个语义块
├── Markdown知识库: 81篇学习材料 → 1885个语义块

  └── 云端: SiliconFlow BGE API (Docker/生产环境查询)
- 检索: 混合检索 = 语义向量(Dense) + 关键词匹配(Jaccard) + RRF融合

- 重排序: 基于领域术语命中+覆盖率+质量分+实现意图检测的轻量重排
- 可追溯: 每个回答附来源标注(教材章节/PDF页码/Markdown章节)
- 质量控制: 自动过滤目录页/版权页/前言/小结等低价值段落
```

**对比赛要求的满足**:
- ✅ 知识库构建(结构化、体系化的三层知识库)
- ✅ RAG(混合检索+Dense+Keyword+RRF三引擎)
- ✅ 知识权威可信(教材来源)
- ✅ 内容可追溯(页码/章节标注)

**技术亮点**:
- 父子块策略：检索用短子块提高精度，返回完整父块保证上下文完整
- 领域术语增强：对"多模态""ReAct""Tool Calling"等30+专业术语加权

### 模块二：编程能力真实性验证闭环 ✅ 已完成

> **状态：这是我们的"杀手级"差异化功能，从计划变为完整实现**

```
核心理念: 代码通过 ≠ 能力真实。学生必须完成「代码+答辩+修复」三关才算过关。

完整流程:
1. 学生编写代码并通过自动测试 → code_passed
2. 系统基于学生本人的代码生成个性化追问(defense questions)
   - "你为什么选择这个数据结构而不是X？"
   - "如果数据量从1万变成1亿，你的方案还成立吗？"
   - "这个函数的时间复杂度是多少？如何优化？"
3. 学生在限定时间内回答答辩问题
4. AI 对学生回答进行实质性评审(非关键词匹配)，AI不可用时自动降级为规则评分
5. 系统注入代码故障，学生需在规定时间内修复(repair)
6. 三关全部通过 → verified = True，能力标记为"已验证"

技术实现:
├── capability_sessions 表：记录每次验证会话的完整状态
├── 答辩评分引擎：AI评审 + 关键词兜底双通道
├── 故障修复注入：基于习题类型自动生成针对性bug
├── 过程事件记录：编码行为日志(非作弊检测，纯学习证据)
├── 旗舰题标准：只对符合标准的"旗舰题"开放能力验证
└── 跳过机制：允许学生仅以测试分数完成关卡
```

**关键技术决策（与原始方案的重要区别）**:
- **不输出作弊概率**：过程事件只作为学习证据，不作为惩罚依据。这避免了"监控学生"的伦理争议
- **旗舰题标准**：旧题需按标准重制后才开放验证，保证质量
- **AI评审为主、规则兜底**：AI可用时做实质性深度评审，不可用时自动降级

**API端点**:
```
POST /api/capability/sessions          → 创建验证会话
POST /api/capability/sessions/{id}/events → 记录过程事件
POST /api/capability/sessions/{id}/code-passed → 标记代码通过
POST /api/capability/sessions/{id}/defense → 提交答辩
POST /api/capability/sessions/{id}/repair → 提交修复
GET  /api/capability/sessions/{id}/review → 获取回顾(含答案对比)
GET  /api/capability/scores              → 获取所有实验分数
```

**对比赛要求的满足**:
- ✅ 创新性: 代码通过≠能力真实的三关验证机制
- ✅ 深度贴合场景: 编程作业/实验课的真实痛点
- ✅ 复杂问题求解: 个性化追问生成+AI评审

### 模块四：Function Calling 智能工具链 ✅ 已完成

> **状态：从零构建了一套完整的工具调用系统**

```
可用工具(4个):
├── web_search: Tavily advanced search
│   - 查询规范化(歧义词固定到AI语境)
│   - 日语过滤
│   - URL/内容去重
│   - 域名可信度评分(.gov/.edu/arxiv等加分)
│   - 词法相关度重排
│
├── knowledge_search: 平台内部RAG检索
│   - 同模块一的混合检索引擎
│
├── analyze_learning_data: NL2SQL学情分析
│   - 模型生成SQL → 安全校验 → 执行 → 返回分析
│   - 严格只读、单表、当前用户
│   - 禁止INSERT/UPDATE/DELETE/DROP等危险操作
│
└── generate_mind_map: 确定性SVG思维导图
    - 左到右树布局算法
    - 持久化存储(去重)
    - 可点击放大
    - 中文字体优化

工具调度:
- 工具规划器(Tool Planner): 模型决策"是否需要工具/需要哪些工具"
- 规则约束: 不是权限展示，工具只在真正需要时调用
- 多工具并行: 可同时调用互补工具(如搜索+知识库)
```

**关键设计决策**:
- 工具是"权限"不是"义务"：模型判断是否需要，不做无意义调用
- 搜索歧义词固定到AI语境："记忆"→"AI Agent memory"，避免搜到语言学/心理学
- Tavily高级搜索+轻量质量控制：不依赖大模型过滤，确定性规则保证低延迟

## 十一、核心结论

```
v1 定位: 一个合格的"助学工具"
        — 刷题、答疑、学习路径，100个竞品都在做

v2.1 定位: AI时代的"能力真实性守护者"
        — RAG知识库让回答有据可查
        — 能力验证让代码≠能力
        — 编程实验室让学习发生在真实环境中
        — Function Calling让AI从"对话机器人"升级为"智能工具人"
        — 从"用AI帮你学"到"用AI帮你真正学会"
```

**我们的故事线(比赛答辩用):**

> "AI正在摧毁计算机教育的根基——学生用AI秒解所有作业，但什么都不会。我们做了一个系统，把AI从'作弊工具'变成'能力锻造工具'。
>
> 技术上：4887个文档块的专业知识库支撑RAG权威回答，混合检索+RRF融合保证检索质量，父子块策略保证上下文完整。
>
> 创新上：代码通过≠能力真实——学生必须通过答辩和故障修复两重关卡，系统才标记'能力已验证'。这不是作弊检测工具，而是让每一个学生的真实能力变得可见、可度量、可提升。
>
> 体验上：Trae风格的编程实验室提供完整IDE体验，Function Calling让AI自主调用搜索/知识库/学情分析/思维导图，真正实现伴随式智能学习。"
