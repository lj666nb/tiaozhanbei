# 项目 11：有依据的回答——引用追溯与安全降级

## 一、检索到了资料，然后呢？

上一节我们拿到了检索结果：

```python
evidence = [
    {"id": "refund-1", "text": "实体商品签收后7天内可申请退款", "score": 2},
    {"id": "refund-2", "text": "退款审核通常需要1个工作日", "score": 1},
]
```

光有这些材料还不够。我们还需要：
1. **基于证据生成回答**——不编造证据中没有的信息
2. **标注引用来源**——每句话来自哪篇文档
3. **没有证据时安全降级**——说「我不知道」而不是胡编

### 什么是「有依据的回答」？

> 🧠 **关键概念：Grounded Answer（有依据的回答）** 指的是回答中的每一个事实都可以追溯到给定的证据文档。与之相反的是**幻觉（Hallucination）**——模型在没有证据的情况下凭「常识」或训练记忆编造回答。
>
> ```
> ❌ 无依据："退款一般3-5个工作日到账" ← 证据里没写，模型在编
> ✅ 有依据："根据退款政策[refund-2]，审核通常需要1个工作日" ← 逐字引用了证据
> ```
>
> **降级不是异常处理**——没有检索到证据是正常业务情况（知识库不可能覆盖所有问题）。降级路径应该是设计的一部分，不是 `except Exception` 的兜底。

### 本节目标

1. **先理解**：引用追溯（Citation）和降级（Degradation）的工程原则
2. **再实现**：`build_grounded_response`——证据拼接、回答生成、引用标注
3. **后验证**：无证据不编造、引用与内容一一对应、最多使用 3 条证据
4. **最终验收**：空证据、正常证据、证据过多三种场景全覆盖

## 三、先做空证据判断——这是第一道防线

> 🧠 **设计原则：Early Return（早返回）**。空证据是最好的判断时机——此时不需要调用模型、不需要拼 prompt、不需要消耗 API 费用。直接返回预定义的降级回答即可。

```python
def build_grounded_response(question, evidence):
    """基于证据生成回答，无证据时安全降级。
    
    参数：
        question (str): 用户问题（非空字符串）
        evidence (list[dict]): 检索结果，每项含 id、text、score
    
    返回：
        dict: {
            "answer": str,       # 回答正文
            "citations": [str],  # 引用的证据 ID 列表
            "needs_human": bool, # 是否需要转人工
        }
    
    核心规则：
        1. 无证据 → needs_human=True，不调用模型，不编造回答
        2. 有证据 → 最多使用 3 条，citations 只包含实际使用的证据 ID
        3. answer 必须基于 evidence 中的 text——不得凭空生成
    """
    # 1. 输入校验
    if not isinstance(question, str) or not question.strip():
        raise ValueError("question 必须是非空字符串")
    if not isinstance(evidence, list):
        raise ValueError("evidence 必须是列表")
    for i, item in enumerate(evidence):
        if not isinstance(item, dict) or "id" not in item or "text" not in item:
            raise ValueError(f"evidence[{i}] 缺少 id 或 text 字段")
    
    # 2. 空证据 → 降级（不调用模型，零成本）
    if not evidence:
        return {
            "answer": "暂未找到可靠依据，已为你转接人工客服。",
            "citations": [],
            "needs_human": True,
        }
    
    # 3. 有证据 → 取前 3 条，生成有依据的回答
    top_evidence = evidence[:3]
    
    # 拼接证据文本
    context_parts = []
    for item in top_evidence:
        context_parts.append(f"[来源:{item['id']}] {item['text']}")
    context = "\n".join(context_parts)
    
    # 生成回答（基于证据，不添加外部知识）
    answer = f"根据资料：{'；'.join(item['text'] for item in top_evidence)}"
    
    # 只引用实际使用的证据
    citations = [item["id"] for item in top_evidence]
    
    return {
        "answer": answer,
        "citations": citations,
        "needs_human": False,
    }
```

> 🧠 **为什么最多 3 条证据？** 模型的上下文窗口虽然很大，但证据不是越多越好。塞入 20 条相关性一般的文档会导致模型「注意力分散」——它可能从最相关的 3 条中找到答案，然后加上第 17 条中的无关信息（数据污染），产生错误的回答。**3 条是一个经验值**：足够覆盖大部分问题，又不会让上下文过于嘈杂。

## 四、引用必须和使用的证据一一对应

这是一个常见的工程错误：

```python
# ❌ 错误：把所有检索结果都列为引用
citations = [item["id"] for item in evidence]  # 包括没用于回答的文档

# ✅ 正确：只引用实际拼接到 answer 中的文档
citations = [item["id"] for item in top_evidence]  # 最多 3 条
```

> 🧠 **为什么不能「全标为引用」？** 引用的目的是让用户或审核者能**追溯**回答中的每一条信息。如果把没使用的文档也标注为引用，当用户点击「来源」发现和回答内容无关时，会降低对整个系统的信任。「有引用」不等于「引用正确」。

## 五、降级路径——正常业务分支，不是异常

```text
需要降级的场景                    降级策略
────────────────────────────────────────────
检索返回空列表                   → needs_human=True，预定义文本
检索超时（服务不可用）             → needs_human=True，"检索服务暂时不可用"
模型调用超时                     → needs_human=True，"回答生成超时"
引用校验失败（模型引用了不存在的ID）→ needs_human=True，记录日志
用户明确要求人工                  → needs_human=True，最高优先级
```

> 🧠 **工程思维：降级是「分支」，不是「兜底」。** 在状态图中，降级路径和正常路径应该是**平级的**——都有明确的节点、边和状态转换。不要把所有失败都塞进一个 `except Exception` 然后返回「系统错误」——用户不知道发生了什么，运维也无法排查。

## 六、完整流程：检索 → 回答 → 降级

```python
# 在 LangGraph 图中整合检索和回答
def grounded_answer_node(state):
    """有依据回答节点：检索 + 回答 + 降级。"""
    question = state["question"]
    evidence = state.get("evidence", [])
    
    result = build_grounded_response(question, evidence)
    
    if result["needs_human"]:
        return {**result, "trace": ["grounded_answer", "degraded_to_human"]}
    else:
        return {**result, "trace": ["grounded_answer"]}

# 图中加入条件路由
builder.add_conditional_edges(
    "grounded_answer",
    lambda state: "human" if state.get("needs_human") else "respond",
    {"human": "human_node", "respond": "finalize_node"},
)
```

## 八、常见错误速查

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 回答中包含证据中没有的信息 | 模型在拼接文本外自己「补全」了内容 | 在 prompt 中加「只根据给定资料回答，不得使用外部常识」 |
| 无证据时仍调用了模型 | 空证据判断放在了模型调用之后 | 把 `if not evidence` 放在函数最前面 |
| citations 数量不等于实际使用的证据数 | 没做截断，或把所有检索结果都列为引用 | 确保 `citations` 只包含 `top_evidence` 的 ID |
| 降级回答写成异常处理 | 降级逻辑放在 `except Exception` 块中 | 把降级设计为平级的 `if/else` 分支 |
