# 项目 3：让 AI 边想边说——流式输出与健壮配置

## 一、我们要解决什么问题

上一节的聊天程序有一个体验问题：输入问题后，屏幕空白好几秒，然后「啪」地一下整段回答全部出现。

这和 ChatGPT 的体验完全不同——ChatGPT 是一个字一个字「打出来」的，你不需要等它想完就能开始读。这种「边生成边显示」的技术叫做**流式输出（Streaming）**。

### 流式 vs 非流式：不只是「快慢」的区别

> 🧠 **关键概念：首字时间（TTFT, Time-To-First-Token）**——从发送请求到屏幕上出现第一个字的时间间隔。`invoke()` 的 TTFT 等于「整个回答的生成时间」（比如 5 秒），而 `stream()` 的 TTFT 可能只有 0.3 秒。用户感知的不是「总时间变短了」，而是**「有东西出来了，系统在干活」**——这在 UX 心理学中叫「感知性能」。

| | `invoke()` | `stream()` |
|---|---|---|
| 用户体验 | 等全部生成完 → 一次性显示 | 逐字/逐词出现，像 ChatGPT |
| 首字时间 | = 总生成时间（长） | 远小于总生成时间（短） |
| 返回类型 | `AIMessage`（完整对象） | `AIMessageChunk` 迭代器（片段序列） |
| 代码复杂度 | 一行 `response = model.invoke(messages)` | 需要 `for chunk in model.stream(messages)` |
| 适用场景 | 后台批处理、短回答、只关心最终结果 | 聊天界面、长回答、需要交互感的场景 |

### 本节目标

1. **先理解**：`stream()` 的迭代器模式和 `invoke()` 的本质区别
2. **再实现**：写出流式循环，逐片段打印并累积完整文本
3. **后健壮**：处理空片段、异常结构、网络超时——写出「不会崩」的代码
4. **最终提取**：把片段规范化逻辑提取为 `normalize_stream_chunks` 函数

## 三、先写出最小流式代码

### 3.1 理解迭代器模式

> 🧠 **Python 预备知识：迭代器（Iterator）** 是一个可以逐个产生值的对象。`for item in iterator` 的每一次循环中，`item` 拿到的是「当前这一个」值，不是「迄今为止所有的」。`model.stream(messages)` 返回的就是一个迭代器——每个 `chunk` 是模型刚生成的**新片段**，不是累积结果。

```text
模型内部生成: "你" → "好" → "，" → "我" → "是" → "A" → "I" → "助" → "手"
                ↓      ↓      ↓      ↓      ↓      ↓      ↓      ↓      ↓
stream() 产出: chunk1 chunk2 chunk3 chunk4 chunk5 chunk6 chunk7 chunk8 chunk9
```

### 3.2 写出流式循环（`app.py`）

```python
# app.py —— 流式输出版
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI

load_dotenv()

api_key = os.getenv("LLM_API_KEY")
if not api_key:
    raise RuntimeError("缺少 LLM_API_KEY")

model = ChatOpenAI(
    model=os.getenv("LLM_MODEL", "deepseek-chat"),
    api_key=api_key,
    base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
    temperature=0.2,
    timeout=30,
    max_retries=2,
)

messages = [
    {"role": "system", "content": "你是课程助教。回答简洁明了。"},
    {"role": "user", "content": "请用三句话介绍 Python。"},
]

# ===== 流式调用的核心逻辑 =====
full_text = []  # 累积所有片段，最后拼成完整回答

for chunk in model.stream(messages):      # stream() 返回迭代器
    text = chunk.content                   # .content 是「本次新增片段」
    if isinstance(text, str) and text:     # 只处理非空字符串
        print(text, end="", flush=True)    # end="" 不换行，flush=True 立即显示
        full_text.append(text)             # 收集片段

print()  # 流式输出结束后换行
answer = "".join(full_text)  # 拼接完整回答
print(f"\n[完整回答共 {len(answer)} 字]")
```

运行它：

```bash
python app.py
```

你会看到文字像打字一样逐字出现——这就是流式输出的效果。

> 🧠 **`flush=True` 是什么？** Python 的 `print()` 默认有缓冲机制——内容先放在内存缓冲区，等积累到一定量或遇到换行符才真正输出到屏幕。`flush=True` 强制立即刷新缓冲区，让每个字一生成就显示。这不是 LangChain 的功能，是 Python 的标准做法。

### 3.3 流式调用后仍需保存完整回答

即使使用了流式输出，最终的完整文本仍然需要写回消息历史：

```python
messages.append({"role": "user", "content": user_text})
answer = stream_answer(model, messages)       # 流式输出 + 返回完整文本
messages.append({"role": "assistant", "content": answer})  # ← 写回完整文本
```

如果只追加流式片段而不保存完整回答，下一轮 `invoke(messages)` 时模型就看不到 assistant 的回复——多轮记忆就断了。

## 四、为什么片段不总是字符串？——防御性编程

### 4.1 问题：外部数据不可信

> 🧠 **工程原则：永远不要假设外部数据的格式。** `chunk.content` 的值取决于模型供应商的实现。DeepSeek 可能返回字符串，OpenAI 可能返回字符串，但某些供应商可能返回：
> - `None`（空片段）
> - `""`（空字符串）
> - `[{"type": "text", "text": "你好"}]`（结构化内容块列表）
> - 带 `content` 属性的对象（而非字典）

如果你直接写 `str(chunk.content)`，`None` 会变成字符串 `"None"`——用户会在回答中看到莫名其妙的「None」字样。

### 4.2 解决方案：在边界统一规范化

在数据进入业务逻辑之前，先把它规范化为统一的格式。这就是 `normalize_stream_chunks` 的职责：

```python
# solution.py —— 流式片段规范化
def normalize_stream_chunks(chunks):
    """把各种模型供应商的流式片段规范化为一个完整字符串。
    
    支持的片段类型：
        - 普通字符串（直接拼接）
        - None / 空字符串（忽略）
        - {"content": "..."} 字典
        - 带 .content 属性的对象（如 AIMessageChunk）
        - content 为 [{"type": "text", "text": "..."}] 的内容块列表
    
    不支持的结构抛出 ValueError（明确失败 > 静默吞错）
    """
    parts = []
    
    for chunk in chunks:
        # 1. 跳过空值
        if chunk is None:
            continue
        
        # 2. 提取 content
        if isinstance(chunk, str):
            content = chunk
        elif isinstance(chunk, dict):
            content = chunk.get("content")
        elif hasattr(chunk, "content"):
            content = chunk.content
        else:
            raise ValueError(f"不支持的片段结构: {type(chunk)}")
        
        # 3. 再次跳过空值
        if content is None or content == "":
            continue
        
        # 4. 处理 content 的不同类型
        if isinstance(content, str):
            parts.append(content)
        elif isinstance(content, list):
            # 处理结构化内容块 [{"type":"text", "text":"..."}]
            for block in content:
                if isinstance(block, dict) and block.get("type") == "text":
                    text = block.get("text")
                    if isinstance(text, str) and text:
                        parts.append(text)
        else:
            raise ValueError(f"不支持的 content 类型: {type(content)}")
    
    return "".join(parts)
```

> 🧠 **为什么 `None` 不能直接 `str()` 转？** Python 的 `str(None)` 会返回字符串 `"None"`（四个字母 N-o-n-e）。用户会在回答中看到这个字面值，非常困惑。正确做法是检测到 `None` 就跳过（`continue`）。

## 五、加入可执行的错误提示——让程序「崩得优雅」

### 5.1 错误处理不是「加分项」

> 🧠 **工程思维**：在 AI 应用中，错误是**必然发生的**——网络抖动、API 限流、Key 过期、模型超时……你会遇到所有这些。好的错误处理不是在代码写完后再「补一圈 try-except」，而是**从一开始就把每种失败模式对应的用户提示写清楚**。

```python
def stream_answer(model, messages):
    """流式输出模型回答，返回完整文本。失败时给出可操作的错误提示。"""
    full_text = []
    try:
        for chunk in model.stream(messages):
            text = chunk.content
            if isinstance(text, str) and text:
                print(text, end="", flush=True)
                full_text.append(text)
        print()
        return "".join(full_text)
    except TimeoutError:
        # 超时：网络慢或问题太长
        print("\n⚠️ 请求超时：请检查网络连接，或把问题缩短后重试。")
        return ""
    except Exception as exc:
        # 其他错误：Key 无效、模型名错误、余额不足……
        error_type = type(exc).__name__
        print(f"\n⚠️ 模型调用失败（{error_type}）：请检查 Key、Base URL 与模型名是否正确。")
        return ""
```

> ⚠️ **安全红线**：绝不能在错误消息中打印 API Key 或完整请求头。错误日志应该让用户知道**查什么**，而不是暴露**密钥是什么**。

## 六、重构 `app.py`——接入规范化函数

在 `app.py` 中导入 `normalize_stream_chunks` 并接入 `model.stream()`：

```python
# app.py —— 完整流式聊天
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from solution import normalize_stream_chunks, append_turn_and_trim

load_dotenv()

api_key = os.getenv("LLM_API_KEY")
if not api_key:
    raise RuntimeError("缺少 LLM_API_KEY")

model = ChatOpenAI(
    model=os.getenv("LLM_MODEL", "deepseek-chat"),
    api_key=api_key,
    base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
    temperature=0.2,
    timeout=30,
    max_retries=2,
)

messages = [
    {"role": "system", "content": "你是课程助教。信息不足时先追问。"}
]

print("开始聊天（输入 exit 或 quit 退出）\n")

while True:
    user_text = input("你：").strip()
    if user_text.lower() in {"exit", "quit"}:
        print("再见！")
        break
    if not user_text:
        print("请输入内容")
        continue

    try:
        # 流式输出（逐片段打印 + 累积完整文本）
        print("AI：", end="")
        full_text = []
        for chunk in model.stream(messages):
            text = chunk.content
            if isinstance(text, str) and text:
                print(text, end="", flush=True)
                full_text.append(text)
        print()
        answer = "".join(full_text)
        
        # 使用上一节的函数管理上下文
        messages = append_turn_and_trim(messages, user_text, answer, max_messages=11)
    except TimeoutError:
        print("\n⚠️ 请求超时，请重试。")
    except Exception as exc:
        print(f"\n⚠️ 调用失败（{type(exc).__name__}），请检查配置。")
```

三个必须满足的可观察行为：
1. 代码**逐个遍历** `model.stream()`，不是先收集完再统一打印
2. 在循环内用 `flush=True` 立即输出每个片段
3. 同时累积完整文本，用于写回消息历史

## 七、常见错误速查

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 回答中出现字面 "None" | `None` 片段被 `str()` 转成了字符串 | 用 `if chunk is None: continue` 跳过 |
| 流式输出仍然一次性显示 | 没有用 `flush=True`，或先收集完再打印 | 确认 `print(text, end="", flush=True)` 在循环内 |
| 下一轮模型「失忆」 | 流式输出后只打印了片段，没有把完整文本写回 messages | 确认 `full_text` 被累积，且用 `append_turn_and_trim` 写回 |
| `ModuleNotFoundError` | 没有安装 `langchain-openai` | 确认 `requirements.txt` 中声明了该包 |
| 流式循环抛出 `ValueError: 不支持的片段结构` | 模型供应商返回了未预见的 content 格式 | 在 `normalize_stream_chunks` 中增加对应的分支 |
